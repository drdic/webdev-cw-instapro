Курсовая «Продвинутый JavaScript»

В курсовой вы разберете реальный сценарий, с которым часто сталкиваются разработчики: доработка чужого кода.
Готовый код нужно проанализировать и понять, какие изменения сделают его лучше. Так вы сможете использовать именно те навыки, которым учились в модуле.

Задание состоит из основной части курсовой и дополнительного задания.

Основные условия курсовой работы
К нам пришел заказчик с интересной задачей.
Он хочет создать аналог популярной социальной сети для обмена фотографиями и запустить его в России.

Хорошая новость: у заказчика уже есть API для первой версии приложения: 
https://github.com/AlenaSol/webdev-hw-api/blob/main/pages/api/v1/%5Bkey%5D/instapro/README.md 

Он уже пытался работать с другими разработчиками, но они не закончили проект и увеличили цену. 
Мы пообещали выполнить проект быстрее, дешевле и качественнее.

Мы согласились воссоздать работу предыдущих разработчиков, чтобы показать, что мы умеем. Вот ссылка на их прототип веб-версии: https://glebkaf.github.io/webdev-cw-instapro/.
У нас нет доступа к исходному коду. Но мы будем опираться на прототип и попробуем сделать приложение удобным.

Алёна Юдина начала работать над нашей версией приложения, но затем нашла другую работу и не закончила проект. 
Ее работу можно найти в репозитории по адресу: https://github.com/Mielilon/webdev-cw-instapro.git.

Что успела сделать Алёна Юдина
1. Создала структуру приложения: переключение между страницами, базовое разделение на модули и компоненты.
2. Полностью реализовала авторизацию и регистрацию.
3. Создала компонент для загрузки фотографий в облако.
4. Разработала компонент для шапки сайта.
5. Сверстала список постов, но не связала его с API.
6. Что осталось доделать
7. Чтобы повторить конкурентов, нужно:

- интегрировать верстку списка постов с API,
- реализовать страницу добавления поста,
- реализовать страницу с постами конкретного юзера,
- реализовать функционал лайков.

Дополнительное задание
Заказчику мало, чтобы приложение работало на уровне конкурентов. Он хочет, чтобы интерфейс был интереснее и понятнее, чем у конкурентов.
Разумеется, новые особенности интерфейса потребуют доработок. Поэтому перед началом работы оцените задачи и определите, сколько часов потребуется дополнительно.
Зафиксируйте эту оценку: помните, что любые дополнительные договоренности с заказчиком нужно согласовывать.

Условия курсовой — и основные, и дополнительные — на этом заканчиваются. 
Теперь мы дадим общие, а затем и подробные рекомендации по выполнению курсовой.

Общие рекомендации
Решайте задачи в указанном порядке.
Делайте коммиты результатов чаще. Хороший ориентир — каждый час. Так вы всегда сможете откатиться к актуальной версии.
Ориентируйтесь на прототип: если не уверены, как что-то должно работать, смотрите, как реализовано там.
Используйте готовый компонент для загрузки фотографий в форме добавления поста, как в форме регистрации.
Применяйте компонент шапки на новых страницах так, чтобы шапка не отличалась от шапки на существующих страницах.
Персональная версия API по умолчанию пустая. Добавьте данные через Postman или используйте prod-версию API, пока не реализуете форму добавления в приложении.
Подключайте сторонние библиотеки, например date-fns, в последнюю очередь, когда остальная работа завершена. 
Как перевести date-fns на русский (добавить новую локаль), читайте здесь: https://date-fns.org/v2.29.3/docs/I18n.

Рекомендации по отдельным задачам
В этом блоке мы собрали рекомендации по решению каждой отдельной задачи. Все эти задачи вы уже решали в процессе работы над лентой комментариев.
Не бойтесь чужого кода. Понимание всех его принципов на 100% не нужно, чтобы выполнить задания.
Работа с роутингом и другими сложными элементами может показаться слишком трудной, но помните: вы и не должны менять их логику.

Обращайте внимание на комментарии @TODO в коде. Они указывают на места, где нужно написать свое решение.
Если возникнут трудности, перечитайте рекомендации — в них есть важные моменты, которые помогут успешно завершить работу.
Помните: все эти задачи уже выполнялись ранее.

Интеграция верстки списка постов с API
Обратите внимание на компонент posts-page-component.js, где стоит @TODO. В этом компоненте уже настроено получение постов через переменную posts.
Ваша задача — доработать отображение данных на странице, используя эту переменную.

Сейчас разметка статична и не зависит от данных API. Она показывает заранее прописанные элементы HTML.

Измените render-функцию, чтобы она использовала данные из API для динамического отображения постов. Посмотрите, как это сделано в ленте комментариев для примера.

Проект использует общее API из примера. Когда вы убедитесь, что посты отображаются корректно, откройте файл api.js и замените значение personalKey на любое другое.
Сейчас используется ключ prod, но вы можете ввести свой ключ.

Не беспокойтесь, если посты исчезнут после замены ключа. Это происходит из-за перехода на новую версию ленты, где пока нет постов.
Вы сможете добавить их, когда выполните следующий пункт задания.

Реализация страницы добавления поста
Нужно, чтобы авторизованный пользователь мог добавлять новые посты. Для этого используем компонент add-post-page-component.js.

Шаг первый — доработаем верстку компонента. Добавьте туда:

1. поле ввода текста для описания поста, 
2. область для загрузки изображения.

При работе с существующими компонентами не бойтесь использовать элементы, которые уже реализованы в проекте. К примеру, функциональность загрузки изображений.

Шаг второй — изучим компонент загрузки изображений. Для этого откройте файл 
upload-image-component.js и изучите документацию:

1. Обратите внимание на параметры, которые принимает компонент, и как они используются.
2. Не нужно дорабатывать функцию renderUploadImageComponent, но важно правильно интегрировать ее.
3. Для примера загрузки изображения посмотрите на auth-page-component.js, где изображение загружается при регистрации.

Шаг третий — реализуйте получение данных из поля ввода текста и загрузки изображения. Затем отредактируйте 
index.js:

1. Перейдите в файл index.js. В блоке @TODO доработайте код для добавления поста в API.
2. Сделайте запрос к API и передайте description (описание поста) и imageUrl (ссылку на загруженное изображение).

Убедитесь, что новый пост отображается на странице сразу, без необходимости перезагрузки.
Это может быть подобно проблеме, которую мы уже решали при работе над лентой комментариев.

Реализация страницы с постами отдельного пользователя
Страница, которую вы создаете, похожа на страницу всех постов. У вас есть два пути ее реализации:

1. Доработать существующий компонент. Можно изменить функцию renderPostsPageComponent так, чтобы она показывала посты конкретного пользователя.
2. Создать новый компонент renderUserPostsPageComponent для отображения постов пользователя.

Чтобы получить посты конкретного пользователя, вам нужен его идентификатор (id). Вы можете взять этот id из data-атрибута data-user-id, который есть в компоненте поста.

Обратите внимание на элементы с пометкой @TODO в файле index.js. Эти пометки показывают места, где нужно реализовать логику работы с API и отрисовку компонентов.

Посмотрите на существующую реализацию получения и отображения всех постов. Это поможет вам организовать структуру кода.

Реализация функции лайков
Мы уже работали с лайками в ленте комментариев. Реализация в этом проекте будет похожей, 
только вместо добавления или удаления класса для визуального отображения лайка мы будем использовать изменение ссылок на изображения.

Изображения лайков
- В папке assets/images есть два изображения: активный и неактивный лайк.
- В разметке предусмотрите условие, которое меняет изображение в зависимости от состояния лайка.

Обновление лайков
1. Лайк должен обновляться без перезагрузки страницы.
2. После нажатия на лайк сделайте запрос к API для получения актуальных данных, как в ленте комментариев.

Счетчик лайков
1. Реализуйте счетчик лайков.
2. API возвращает массив пользователей, которые поставили лайки. Чтобы узнать количество лайков, определите длину этого массива и отобразите значение в интерфейсе.

Убедитесь, что лайки работают корректно на странице всех постов и на странице отдельного пользователя.

Дополнительное задание
Придумайте, как улучшить приложение, подумайте об интерфейсных «плюшках», которые просил заказчик, и реализуйте их. 
Укажите в README, что удалось реализовать, а также предварительную оценку доработок в часах.
Поскольку вы должны сами решить, что именно добавлять в интерфейс, мы не говорим, что именно делать. 
Вместо этого мы напомним, что, когда разработчик сдает работу, ее проверяют по списку приемочных критериев.

Приемочные критерии — это список требований от заказчика, по которым он будет проводить приемку готового продукта.
В данном задании приемочные критерии будут также критериями оценки.

Критерии оценки
1. Я, как неавторизованный пользователь, могу смотреть общую ленту постов.
2. Я, как неавторизованный пользователь, могу смотреть ленту постов конкретного пользователя.
3. Я, как неавторизованный, но зарегистрированный пользователь, могу авторизоваться.
4. Я, как незарегистрированный пользователь, могу зарегистрироваться.
5. Я, как авторизованный пользователь, могу лайкать посты и снимать свои лайки.
6. Я, как авторизованный пользователь, могу добавить пост.

Тестирование
Не забудьте провести тестирование приложения, прежде чем сдавать работу! Это очень важно для успеха проекта.
Наша команда QA уже успела изучить приложение конкурентов и подготовить подробный тест-план. 
Придерживайтесь его, чтобы протестировать приложение и убедиться, что оно работает так, как задумано.

Тест-план можно дополнить проверками, которые вы считаете необходимыми.

Тест-план.

1. Авторизация и регистрация:
- Регистрация нового пользователя с правильными данными проходит успешно.
- Если пользователь вводит некорректные данные, например не заполнил одно из полей, интерфейс сообщает об ошибке.
- Интерфейс сообщает об ошибке, если пользователь пытается зарегистрироваться с уже существующим логином.
- Авторизация с корректными данными проходит успешно.
- Если пользователь вводит неверные данные, например несуществующий логин или неправильный пароль, интерфейс сообщает об ошибке.
- После успешной авторизации или регистрации пользователь попадает на страницу с общей лентой постов.
- Авторизация сохраняется после обновления страницы.
- Кнопка «Выйти» делает пользователя неавторизованным.

2. Общая лента постов:
- Приложение открывается на экране с общей лентой постов по умолчанию.
- Авторизованные и неавторизованные пользователи видят общую ленту постов.

3. Лента постов конкретного пользователя:
- Я могу перейти в ленту конкретного пользователя, кликнув по его имени в общей ленте постов.
- Лента постов конкретного пользователя доступна для всех.
- Посты конкретного пользователя запрашиваются из API: user-posts.

4. Авторизованные пользователи могут ставить лайки и дизлайки в общей ленте постов и в ленте постов пользователя. 
Неавторизованные пользователи не могут ставить лайки и дизлайки.

5. Добавление поста:
- Авторизованные пользователи могут добавлять посты с текстом и фотографией.
- Неавторизованные пользователи не могут добавлять посты.
- При добавлении поста проверяется наличие текста и фотографии.

6. Интерфейсные особенности:
- Проверка анимаций и улучшенной навигации.
- Проверка адаптивности и кросс-браузерности интерфейса.
7. Безопасность:
- Проверка безопасности на уязвимости и защита данных пользователей.
- HTML-теги, введенные в формах, отображаются как текст и не срабатывают.
